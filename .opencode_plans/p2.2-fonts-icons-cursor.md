## Spec

Roadmap `docs/roadmap.md` → P2.2: «Fonts, icons, cursor: system font, console
font, UI icons, app icon pack, cursor» con la decisión bloqueada «Fonts / icons
/ cursor | One page, applied to the whole system at once», y el criterio de
hecho «One change updates GTK, Qt, kitty, the shell and the cursor in the same
session».

**Decisiones del dueño (2026-11-04, todas «A»):**

- Una sola preferencia de fuente del sistema que se aplica a GTK/Qt, al shell y
  a la consola; no hay tres ajustes separados.
- Las opciones salen de lo instalado: `fc-list` para fuentes, `/usr/share/icons`
  + `~/.icons` (+ `~/.local/share/icons`) para packs de iconos y cursores. No
  hay listas curadas en el repo.
- «Iconos de UI» solo ofrece las variantes de Material Symbols (Rounded, Sharp,
  Outlined): el shell los dibuja por ligadura.
- El cursor en este plan es «pack instalado + tamaño»; el tintado por paleta,
  los seis diseños y el spinner propio son P2.10.

## Arquitectura

- `vitrail/fonts.py`: las listas vivas (`fc-list`, carpetas de temas) y el
  `apply` que valida cada valor y lo escribe en fontconfig, GTK, qt6ct, cursor y
  entorno. Mismo patrón que `vitrail/monitors.py`: `state` imprime JSON para la
  ventana, `apply` corre desde `scripts/apply-settings.sh`.
- `shell/pages/FontsPage.qml`: la página única, con pestañas Texto / Iconos /
  Cursor, alimentada por `--fonts` (el JSON de `fonts state`).
- Tokens: `fontFamily` e `iconFamily` dejan de ser constantes y pasan a venir de
  `fonts.ini` (shell vivo, sin reiniciar).
- El resto del sistema se aplica por `scripts/apply-settings.sh` (fontconfig,
  gsettings, qt6ct, kitty, `hyprctl setcursor`), disparado por la unidad de
  path al escribir `fonts.ini`.

## Restricciones globales

- Todo elemento visual sale de `kit/`; ni un color, duración o tamaño literal en
  un componente; los literales nuevos van a `kit/tokens.js`.
- Las seis lenguas (`kit/i18n/*.json`) en el mismo cambio que las cadenas; las
  claves de `prefs.map`, `shell/Prefs.qml`, la unidad de path y la tabla del
  README en el mismo cambio que la preferencia.
- Todo programa nuevo (`fc-list`) va a `packages/*.txt`, a `PROVIDED_BY` y a la
  tabla «Runtime dependencies» del README.
- Nada de una preferencia llega sin validar a fontconfig, kitty, qt6ct o
  `environment.d`: un valor que no está en las listas vivas se rechaza y no se
  escribe nada (código 2, como en `monitors apply`).
- Defaults en QML (`shell/Prefs.qml`); un valor guardado siempre gana.
- Sin dependencia nueva de ejecución salvo `fontconfig` (ya presente en
  cualquier escritorio) y las fuentes que el shell ya usaba.

## Review Focus

1. Fuente elegida que ya no está instalada (config copiada de otra máquina) →
   la página la muestra, `apply` **no** escribe ese valor: ese campo cae al
   default (`Roboto`) y el resto (iconos, cursor) se aplica igual; el log dice
   qué se sustituyó.
2. `fonts.ini` recién creado (instalación limpia), o con una clave suelta → la
   página muestra los defaults y ningún selector vacío.
3. Familias con espacios, `&`, `<`, `"` → el XML de fontconfig va escapado y la
   línea de kitty es una sola, sin inyección de directivas.
4. `fc-list` ausente o fallando (listas vacías: no se puede validar) → `apply`
   registra el fallo y **no escribe nada**, para no pisar la configuración
   buena con defaults.
5. `uiIcons` con un valor desconocido → `Tokens.font.iconFamilyOf` cae en
   Rounded; nunca queda un `font.family` inventado en el shell.
